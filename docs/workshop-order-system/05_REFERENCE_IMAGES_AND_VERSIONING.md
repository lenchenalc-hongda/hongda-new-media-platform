# 生产参考图片与版本防错 V1

## 1. 目的

图片不是普通附件，而是车间防错生产基准。

系统要确保车间能够直接核对：

- 正确的花膜图案
- 正确的产品
- 正确的客户确认效果
- 正确的当前版本

## 2. 图片类型

两个入口都支持多图上传：

- 花膜图案
- 产品实物
- 客户确认样/效果
- 大货签样
- 位置/接口标注
- 包装/标签
- 打烊结果
- 不良/风险细节
- 其他生产参考

## 3. 上传体验

### 办公室

- 支持一次选择多张
- 支持拖拽
- 支持粘贴截图
- 支持拍照后从手机浏览器上传
- 上传前选择图片类型
- 可填写说明和版本号
- 上传后可拖动排序

### 车间

- 任务卡片显示当前基准缩略图
- 详情页支持大图预览
- 可在花膜、产品、客户样之间快速切换
- 不需要下载到本地才能查看
- 弱网络下先显示缩略图，再加载原图

## 4. 当前生产基准

图片上传后默认只是“参考资料”，不能自动成为生产基准。

办公室/项目负责人需要创建或更新一个 baseline set，并明确：

- 当前订单版本
- 当前花膜图案
- 当前产品实物
- 当前客户确认样
- 当前大货签样
- 生效说明

车间必须点击：

> 已核对当前版本图片

之后系统记录确认人和时间。

## 5. 版本规则

### 不允许覆盖

- 替换图片 = 上传新记录
- 旧图片保留
- 新图片通过 `supersedes_image_id` 指向旧图片
- 旧图片标记“旧版本/已替代”

### baseline 切换

同一任务只能有一个 CURRENT baseline。

切换时：

1. 原 baseline 变为 SUPERSEDED
2. 新 baseline 变为 CURRENT
3. 车间之前的视觉确认失效
4. 已排期但未开工任务自动回到版本复核
5. 已开工任务触发高风险异常，必须暂停并由主管处理

## 6. 防错检查

系统在排期/开工前自动检查：

- order.version_label = baseline.version_label
- film readiness.version_label = baseline.version_label（适用时）
- current baseline 至少有一张产品图
- current baseline 至少有一张花膜图（已有花膜时）
- 需要确认样时存在客户确认样/大货签样
- workshop_confirmed_at 晚于 baseline 创建时间
- baseline 所有 required item 未被废弃

## 7. 显示规范

### 当前版本

- 绿色“当前生产基准”标记
- 大号版本号
- 首屏显示
- 图片分组明确

### 旧版本

- 灰色“旧版本”标记
- 默认折叠
- 放大图上叠加旧版本提示
- 不允许从旧版本直接点击“确认开工”

### 不一致

红色拦截提示，例如：

> 订单版本 V4，但当前花膜图片为 V3。请办公室更新基准或更正订单版本。

## 8. 图片状态

- UPLOADING
- READY
- FAILED
- QUARANTINED
- SUPERSEDED
- ARCHIVED

上传失败不得生成可用图片记录；病毒/格式校验失败进入 QUARANTINED。

## 9. 文件安全

- 限制 JPEG/PNG/WebP/PDF 等批准格式
- 设置单文件大小上限
- 服务端校验 MIME type
- 文件名不作为唯一标识
- 使用随机 storage path
- 默认私有 bucket
- signed URL 有短有效期
- 不在日志打印 signed URL query 或 secret

## 10. 打烊结果照片

打烊结果照片必须与一次 technical attempt 绑定，不能只挂在申请主表。

建议分类：

- OVERALL_RESULT
- SEAM
- EDGE
- STRETCH_AREA
- ADHESION_TEST
- DEFECT_DETAIL

每次重新打烊形成独立 attempt 和独立结果图组。

## 11. 验收案例

1. 办公室上传 V1 花膜和产品图片，设置基准；车间确认后可排期。
2. 办公室上传 V2 并切换基准；V1 仍可查看，但车间确认自动失效。
3. 订单为 V2、花膜 readiness 仍为 V1；系统阻止开工。
4. 需要客户确认样但未上传；系统阻止进入 READY_TO_START。
5. 打烊完成但无结果图片；系统阻止关闭。
