# Hongda Workshop Order System — 项目框架 V1

## 1. 产品定位

Workshop Order System（WOS）是 Hongda OS 内部的“办公室下单 → 车间确认 → 物料齐套 → 排期 → 技术/生产执行 → 完工关闭”协同系统。

系统不只是把纸质表单电子化，而是把纸质表单背后的生产防错、物料齐套、开工 Gate、技术记录、版本留痕和责任确认变成可执行流程。

## 2. 两个独立入口，一个共享车间中心

### 入口 A：生产下单

面向办公室、销售和项目负责人。用于已经进入大货阶段的订单，把客户要求、产品工艺、签样、花膜、夹具、来料、包装、货期和数量完整交给车间。

### 入口 B：打烊申请

面向办公室、销售和项目负责人。用于验证产品是否可生产、附着力/接口/拉伸/切边/位置是否达标，并由技术员记录实际参数、结果、风险和照片。

### 共享车间中心

两个入口进入同一车间任务中心，但任务类型明确区分：

- 生产任务
- 打烊任务

共享能力：

- 待确认队列
- 物料齐套
- 图片/版本核对
- 排期
- 阻塞原因
- 技术记录
- 三方确认
- 状态历史
- 审计日志
- 附件与照片

## 3. 业务目标

1. 办公室提交后，车间不再依赖微信群、口头说明和散落图片判断生产要求。
2. 车间能够一眼看到：花膜、夹具、来料、签样、图片和资料是否齐全。
3. 未满足开工条件时系统自动阻止进入排期或开工。
4. 生产版本、图片版本、客户确认样和大货签样保持一致。
5. 办公室能实时看到任务为什么未排期、谁在处理、预计何时完成。
6. 打烊参数、结果照片和结论能够直接转为后续生产基准。
7. 所有关键变更可追溯，不允许静默覆盖正式版本。

## 4. 核心防错原则

### 四个必须一致

- 花膜对
- 产品对
- 版本对
- 确认样对

任意一项不一致，任务进入阻塞，不允许开工。

### 六类开工条件

生产任务至少校验：

1. 花膜已到位并核对版本
2. 夹具已到位并确认可用
3. 来料/胶件已到位且数量满足当前批次
4. 当前生产基准图片已核对
5. 大货签样/客户确认样已到位（订单要求时）
6. 技术员和车间主管确认

## 5. 系统角色

- Admin：全局配置、用户权限、字典和审计查看
- Manager：全局任务、排期、异常和资源协调
- Office / Project Owner：创建和补充生产单/打烊申请，确认客户版本与要求
- Sales：查看本人客户项目、提交业务信息、跟进异常
- Technician：接收打烊/调机任务，记录参数、结果、风险和结果图片
- Workshop Supervisor：接单、物料确认、排期、开工放行、暂停和完工确认
- Quality：签样/标准核对、品质 Gate、异常隔离和放行
- Operator：查看已放行任务、执行生产、填写过程记录

## 7. 非目标（V1）

V1 不做：

- ERP 财务/采购/库存总账
- 自动生成最终报价
- 自动承诺货期
- 自动修改客户归属
- 直接替代现有财务系统
- 无人工确认的 Production 上线
- AI 自行改变生产技术结论

## 8. 技术边界

- 正式业务数据未来以 Supabase/PostgreSQL 为 SoT。
- Phase 0 仅做规格、类型、测试和非 Production 脚手架。
- Production schema/RLS/data/env/secrets 必须单独 Human Gate。
- 正式照片必须使用私有存储和授权访问，不允许默认公共链接。
- AI 可以辅助检查资料完整性、总结风险和建议排期，但不能替代技术员/主管签字。

## 9. 成功标准

初步上线后应达到：

- 办公室能在 5 分钟内完成一张资料齐全的生产单或打烊申请。
- 车间无需询问即可知道当前版本、正确花膜、正确产品和客户确认样。
- 缺物料/缺图片/缺签样的任务自动阻塞并显示原因。
- 每个状态变更可追溯到操作者和时间。
- 打烊通过后可一键生成生产单草稿并继承技术参数、风险和图片。
