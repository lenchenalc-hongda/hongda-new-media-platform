# 宏达印业 — 账号人设框架

> 本文档面向内容团队和产品团队，解释账号人设的新工作方式。

## 为什么需要 Account V2？

以前的账号只有一句话的人设描述，系统只用了少数几个字段。

现在系统会严格按照账号配置来：
1. 决定人物身份和说话方式
2. 匹配目标客户和内容栏目
3. 遵守品牌边界和事实规则
4. 执行不同阶段的转化策略

这样每个账号生成的内容才会有真正的差异化，不是换个名字说一样的话。

---

## 三层对比

### 旧逻辑

```
账号 → 只有 name/persona → 传给 AI 但只用了几个字段
     → 所有账号内容风格差不多
     → 靠 name.includes('老板') 判断角色
     → 没有品牌边界检查
```

### 新逻辑

```
账号配置层
    ↓
账号选择与服务端解析
    ↓
Persona Compiler（统一编译人设上下文）
    ↓
任务级人设指令（不同任务只看需要的字段）
    ↓
内容策略 → 角度 → 钩子 → 事实稿 → 人设改写 → 审稿
    ↓
保存账号版本和快照
```

### 三层意义

1. **账号配置层**——一次填写，持续生效
2. **Persona Compiler**——确保所有 AI 调用使用同一个人设
3. **审稿层**——生成后的脚本自动检查是否跑偏

## 字段详解

### 一、人物身份字段（persona_config）

这些字段定义"这个人是谁"。

| 字段 | 说明 | 示例 |
|---|---|---|
| `speaker_role` | 角色类型：owner/sales/technician/consultant/host | "owner" |
| `on_camera_identity` | 出镜身份一句话 | "宏达印业负责人、工厂经营者" |
| `identity` | 人物身份列表（3-5条） | ["宏达印业负责人", "工厂经营者"] |
| `expertise` | 真正擅长什么 | ["印刷工艺判断和设备选型", "产能和成本分析"] |
| `experience_sources` | 判断来源 | ["多年运营工厂经历", "长期接触客户问题"] |
| `core_beliefs` | 长期坚持的原则 | ["买设备不是买参数，是买稳定生产的能力"] |
| `trust_sources` | 客户为什么相信他 | ["多年经验积累的判断力"] |
| `voice_traits` | 说话特征 | ["大方", "稳重", "真诚"] |
| `sentence_rules` | 句子规则 | ["句子长度适中", "讲判断不喊口号"] |
| `jargon_level` | 术语程度 (low/medium/high) | "medium" |
| `emotional_intensity` | 情绪强度 (low/medium/high) | "low" |

### 二、内容定位字段

这些字段定义"这个账号长期做什么"。

| 字段 | 说明 |
|---|---|
| `positioning` | 一句话定位，解决什么问题 |
| `content_pillars` | 内容支柱列表，每条有名称/权重/目的/示例 |
| `main_content_types` | 内容类型（兼容旧字段） |

### 三、品牌边界字段（brand_policy）

这些字段定义"什么能说什么不能说"。

| 字段 | 说明 |
|---|---|
| `allowed_claims` | 可以主动说的品牌表达 |
| `forbidden_claims` | 绝对不能说的表达 |
| `preferred_brand_expressions` | 推荐使用的品牌说法 |
| `sensitive_topics` | 敏感话题 |
| `competitor_policy` | 如何对待竞争品牌 |

### 四、目标客户字段（audience_segments）

每个账号可以有多个客户群体，生成时选择最匹配的那个。

| 字段 | 说明 |
|---|---|
| `name` | 客户群名称 |
| `description` | 客户描述 |
| `main_pains` | 主要痛点 |
| `common_objections` | 常见顾虑 |
| `desired_results` | 希望的结果 |

### 五、平台策略字段（platform_profiles）

不同平台有不同的表达方式。

| 字段 | 说明 |
|---|---|
| `ideal_duration_seconds` | 建议时长范围 |
| `hook_styles` | 适合的钩子风格 |
| `pacing` | 内容节奏 |
| `sentence_length` | 句子长度 |
| `preferred_ctas` | 推荐的转化动作 |

### 六、转化策略字段（conversion_strategy）

不同客户阶段使用不同的转化方式。

| 阶段 | 目的 | 适合的 CTA |
|---|---|---|
| awareness | 建立认知，关注收藏 | "关注"、"收藏" |
| consideration | 引导提供产品信息 | "发产品图"、"告诉我材质" |
| high_intent | 寄样打样 | "寄样测试"、"预约到厂" |
| customer_service | 售后维护 | "联系我们"、"预约调试" |

### 七、知识合规字段（knowledge_scope）

| 字段 | 说明 |
|---|---|
| `allowed_topics` | 可以讲的话题 |
| `restricted_topics` | 受限话题 |
| `requires_evidence` | 需要真实证据才能说的内容 |
| `fallback_language` | 没有资料时使用的安全表达 |

## 如何填写新账号

1. 复制 `src/lib/accounts/templates/account-persona.template.ts`
2. 修改 `id`（唯一）、`name`、`persona_version`（初始1.0.0）
3. 填写 `persona_config`→人物是谁、擅长什么、怎么说话
4. 填写 `audience_segments`→至少2个目标客户
5. 填写 `content_pillars`→至少3个栏目，权重总和100
6. 填写 `platform_profiles`→至少覆盖默认平台
7. 填写 `brand_policy`→绝对不能说的要列清楚
8. 填写 `conversion_strategy`→覆盖四个漏斗阶段
9. 填写 `knowledge_scope`→哪些需要证据
10. 运行 `validateAccountConfig(account)` 校验
11. 添加到 `MOCK_ACCOUNTS_V2` 数组中
12. 上线

## 常见错误

- **虚构经历**：不要编造没有依据的人物经历和客户案例
- **所有账号一样**：每个账号的 audience_segments、voice_traits 应该明显不同
- **权重不成100**：content_pillars 的 weight 总和应该为 100
- **缺少品牌边界**：forbidden_claims 不能为空
- **转化太硬**：awareness 阶段不要用"立即购买"

- [ ] 是否像这个人本人说话？
- [ ] 是否与其他账号明显不同？
- [ ] 是否有明确客户群体？
- [ ] 是否有内容支柱和比例？
- [ ] 是否有品牌和事实边界？
- [ ] 是否有不同漏斗阶段的转化？
- [ ] 是否有知识权限边界？
- [ ] 是否有禁止表达？
- [ ] 是否填写版本号？
- [ ] validateAccountConfig 是否通过？

---

## 版本更新规则

- 首次创建：1.0.0
- 小幅调整（改几个表达）：1.0.x
- 中等调整（改内容支柱比例）：1.x.0
- 重大调整（改角色定位）：x.0.0

每次更新人设后必须在 `updated_at` 记录时间。
