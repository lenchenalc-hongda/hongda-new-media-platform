# 03 客户数据模型

> SPEC_LOCK_VERSION = GLH-SPEC-V1.0
> FROZEN = YES

## Formal entities

At minimum design for:

- `glh_leads`
- `glh_contacts`
- `glh_lead_profiles`
- `glh_conversations`
- `glh_messages`
- `glh_channel_accounts`
- `glh_webhook_events`
- `glh_lead_scores`
- `glh_assignments`
- `glh_tasks`
- `glh_followups`
- `glh_ai_actions`
- `glh_automation_runs`
- `glh_ad_campaigns`
- `glh_ad_creatives`

## Lead profile fields

Support structured fields for:

- customer/company/country;
- WhatsApp/email/web/social identifiers;
- product;
- material;
- product images/media references;
- dimensions;
- quantity;
- artwork/printing area;
- requirement type;
- current printing process;
- pain points;
- test requirements;
- sample availability;
- purchase timeline;
- machine capacity/automation requirements when applicable;
- owner;
- lifecycle state;
- conversation mode;
- grade;
- score;
- completeness;
- next follow-up;
- source/campaign/ad/adset/creative attribution when available.

## De-duplication

Strong deterministic identifiers first:

- provider external contact ID;
- normalized WhatsApp/phone;
- normalized email.

Weak/fuzzy matches may only suggest a possible duplicate. They must not auto-merge records without safe deterministic evidence or human confirmation.

## Messages

Store original inbound/outbound message facts:

- provider message ID;
- conversation/contact/lead link;
- direction;
- actor type AI/human/customer/system;
- text;
- attachment/media metadata;
- provider timestamp;
- status/error metadata.

AI summary does not replace message history.

## Storage

Customer-uploaded images/files use private storage with authorized access, not public buckets by default.

## Database security

Current Supabase behavior must be respected:

- Data API exposure/grants and RLS are separate concerns;
- explicitly grant only intended API access;
- RLS required on exposed tables;
- `anon` has no GLH business access;
- high-risk mutations should prefer controlled server/RPC paths;
- no service-role secret in the client.

Create indexes for external IDs, owner/state, follow-up date, conversation lead, created time, and webhook idempotency keys as required.
