# 02 客户生命周期与状态机

> SPEC_LOCK_VERSION = GLH-SPEC-V1.0
> FROZEN = YES

## Main lifecycle states

```text
NEW
AI_QUALIFYING
WAITING_CUSTOMER
READY_FOR_HUMAN
HUMAN_FOLLOWING
QUOTATION
SAMPLE
NEGOTIATION
WON
LOST
DORMANT
INVALID
```

These are system states. Do not allow arbitrary labels such as "follow later" or "some interest" as replacement states.

## Conversation mode (separate from lifecycle)

```text
AI_ACTIVE
HANDOFF_PENDING
HUMAN_ACTIVE
PAUSED
```

Lifecycle state and conversation mode must be separate fields.

## Priority grade (separate from lifecycle)

A / B / C / D is prioritization only. D is not automatically INVALID.

## State rules

AI can move early qualification states only:

- NEW → AI_QUALIFYING
- AI_QUALIFYING ↔ WAITING_CUSTOMER
- AI_QUALIFYING / WAITING_CUSTOMER → READY_FOR_HUMAN

Human/approved server actions control consequential business transitions such as:

- HUMAN_FOLLOWING
- QUOTATION
- SAMPLE
- NEGOTIATION
- WON
- LOST
- INVALID

Every stage change records previous state, next state, actor, timestamp and reason/context.
