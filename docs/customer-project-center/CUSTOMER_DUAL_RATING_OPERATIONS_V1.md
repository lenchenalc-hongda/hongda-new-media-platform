# CPC 双评级与客户销售维护闭环｜产品规格、权限及生产验收 V1

状态：2026-10-25 已实现 Dev 试运行版本；Production 发布必须以实际 CI / RLS / 数据库迁移核验为依据。范围限 CPC；不改变外部客户池、财务与提成系统。

## 一、客户双评级

### 实际 R（财务自动核算，不可手填）

以**最近12个完整自然月**的有效人民币净回款为依据，正式财务接口需先独立核对，单个客户依据稳定外部 ID 汇总，不依据客户名称模糊匹配。统计应扣除对应退款、冲销，检查重复收款与跨公司/外币换算。

| R等级 | 金额（元） |
| --- | --- |
| SS | > 300万元 |
| S | > 100万元且 <= 300万元 |
| A | >= 50万元且 <= 100万元 |
| B | >= 10万元且 < 50万元 |
| C | >= 1万元且 < 10万元 |
| D | < 1万元，前提是财务来源覆盖完整且核实为有效数据 |
| N | 财务未接入、历史不完整或尚未完成核实 |

300万整属于S，100万整属于A，50万整属于A，10万整属于B，1万整属于C。**0元仅在完整财务覆盖核实后才是D**。实际 R 与销售个人主观评估、项目报价、提成和财务权限绝对隔离。

**现阶段功能性限制：** 权威车间系统 `receiptRecords` 尚无获批的 CPC 只读增量同步契约；因此 UI 真实显示 R-N 及“财务数据尚未接入”。这不是把所有客户标为财务真实D；不得使用手填历史金额冒充R。

### 潜力 P（业务评估、经理审核）

五项指标均为0–5整数。权重：可开发采购规模30%，工艺产品匹配25%，实际项目机会20%，客户决策触达15%，长期复购10%。潜力总分是 `6*规模+5*匹配+4*项目+3*决策+2*复购`。

| P等级 | 得分 |
| --- | --- |
| SS | 90–100 |
| S | 80–89 |
| A | 70–79 |
| B | 55–69 |
| C | 35–54 |
| D | 0–34（经过充分评估） |
| N | 未评、草稿、待审核且此前未批准 |

提交审核前必须包含客户事实依据（至少20字）、具体机会（至少10字）、下一步销售动作（至少5字）、下一步检查日期。预计可开发年采购金额为**主观机会估计**，不属于实际回款/订单/销售业绩。

**批准发布逻辑**：
- 业务员对其外部客户池映射的真实客户可以新建/编辑草稿并提交。
- 对临时客户仅创建人可以初评；经理/管理员可处理同机构范围的客户。
- 经理/管理员审核；仅 approved 的 P等级作为正式发布等级。
- 任何已批准评分被修改进入待审核后，保留上一份已审核等级直到新评分再次批准；不得让草稿覆盖已批准历史。
- 退回需填写原因；分数、材料、下一步、审核和旧值有审计轨迹；每次保存使用 version 乐观锁，避免覆盖。
- 未核实事实不应选择0分后直接交正式评分；如无证据应保持P-N。

## 二、客户销售工作与维护人

客户维护人来源：`workshop_customer_pool` 的 `external_owner_reference` → `cpc_external_profile_mappings`（active）→ 同org、仍active的 `profiles`。不同步新“客户归属”字段，不允许通过评级重新分配归属；无映射需显示“待映射”，不能猜姓名。

CPC客户列表：
- 展示R等级、审核生效的P等级及当前外部维护人。
- 提供“我负责的客户”（比较映射的真实 profile ID）、“已审核高潜客户（P-A/P-S/P-SS）”、“潜力待审核”、“开发动作到期检查”等过滤。
- 高潜客户展示负责人、已记录的下一步行动及检查日期（不存在则显示待补）。
- 销售动作是一份客户经营计划记录，**不会自动成为正式任务**，防止批量假任务。需要明确责任、期限和闭环时，通过原CPC跟进/项目接口形成已确认任务。

CPC客户详情：
- R金额事实未知→R-N并解释原因；P未审批→P-N，显示待审核评分而非正式成绩。
- 业务员五项评分、证据、机会、预计年可开发采购金额、下一步及日期。
- 管理者查看本轮评估并批准或退回，审计记录自动保存。
- R高/P高→维护和增量开发；R低/P高→重点突破；R高/P低→稳定维护；R低/P低→常规经营；任一维度N不得推断完整价值。R-N/P高仍可依据已确认P提出明确开发动作，但不得假定实际收入。

与已有回访算法隔离：
- CPC现有`old-customer-proactive` A/B/C/UNKNOWN是关系回访建议（30/60/90天），不是 R 或 P；保持原逻辑和任务状态。
- 评级不参与员工提成、薪资、财务锁定、回款记账、客户主数据改动或客户负责人自动变更。

## 四、开发库真实事务演练

在专用Supabase开发项目 `hongda-review-dev`（不是Production）创建测试临时客户的数据库事务，使用开发库现有 Sales 与 Admin 用户上下文分别执行：
1. 销售创建草稿/提交100分评分。
2. 销售尝试审批：拒绝。
3. 经理审批：P-SS正式发布、状态approved、版本从1→2。
4. 旧版本重复审批：VERSION_CONFLICT。
5. 审计日志应有“提交、审批”2条。
6. `ROLLBACK` 回滚全部临时客户和潜力评分测试数据。

数据库权限另验证：anon不可读表或执行新增RPC；authenticated只允许RLS SELECT，不授予直接INSERT/UPDATE/DELETE。

## 五、Production独立验收

1. 核验评审HEAD和CI全绿、Next.js Preview READY、相关模块路由正常。
2. 验证Production已有CPC对象完整、migration未执行、财务权威接口仍未通过审批。
3. 仅在owner批准**此增量schema/RLS/RPC + 明确HEAD的上线窗口**后先执行数据库新增 migration（不改任何原客户或财务表），检查安全顾问与RLS权限。
4. 再合并已测试HEAD并核实Production READY+正式域名映射+运行错误。
5. 使用有权限的真实账号执行最小闭环（新建草稿→提交→审批→列表更新）。不得创建伪造真实客户评级。
6. 仅“删除新功能 UI/路由”可通过回滚代码恢复界面；数据库新增表只保留禁用而不删生产业务数据，必须有专门审批才能清理。

尚未接入的财务同步和历史R评级必须作为独立后续项目，不得借本次迁移篡改生产收款或提成。
