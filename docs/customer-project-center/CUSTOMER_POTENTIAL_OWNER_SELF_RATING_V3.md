# HongdaOS CPC｜客户潜力 P 评级负责人自主评定 V3

规则确认时间：2026-10-25。**替代旧的潜力评级“提交管理者审核”流程。**

## 1. 两种客户评级仍完全独立

- **R 实际评级**：由财务权威数据确认的最近12个月净回款自动计算；SS>300万，S>100万至300万，A50–100万，B10–<50万，C1–<10万，D<1万，N为缺少可核实财务数据。不得手填R，不得将尚未同步的回款判为0。
- **P 潜力评级**：内部对未来12个月可争取订单潜力的判断，**客户负责人或关联项目负责人自己评分、保存后立即生效，无须经理审核。**
- 已确定的评分项与权重不变：可开发采购规模30%，工艺与产品匹配25%，明确项目机会20%，决策触达15%，长期合作价值10%。各0–5分，系统合计为百分制。SS90–100、S80–89、A70–79、B55–69、C35–54、D0–34、N未生效/未评级。
- 五项评分必须完成，并记录至少20字客户事实与可核实依据；**保存潜力评级并生效**自动换算正式P等级。评分修改无需审批，但不得跳过证据、单位权限校验或历史审计。
- 已存在的旧版草稿/待审记录**不自动转正**。原拥有权限的负责人在页面重新核对五项评分和依据，主动点击保存后，才发布P等级。已批准的历史等级仍保留在数据和审计中。

## 2. 负责人可改什么

- 已登录、在本组织具有有效admin或manager角色：继续可以负责内部P评分的日常维护，但不存在审批流程。
- sales角色的**外部客户池权威映射负责人**：允许修改该客户P评分。
- sales角色的**临时客户创建人**：允许修改自己创建的临时客户P评分。
- sales角色的**当前有效关联项目负责人**：如果 `cpc_projects.owner_profile_id` =当前员工profile，项目在 `active`、`paused` 或 `won`，且同组织、客户状态有效，则也允许修改该客户的P评分。`lost`、`cancelled` 项目不构成额外写入许可。**项目负责人不等于客户池归属人**；该权限只适用于P评级。
- 仅被分配回访任务、非本组织、无客户或项目归属的其他业务员：**不能修改**该客户P评级。
- 评级权限扩展**不能用于修改客户归属、备注、销售开发计划或财务数据**；前两类编辑权限继续采用原有`cpc_can_assess_customer_rating`。同一个客户的多个有效项目负责人会共享**一个当前生效的客户级P等级**，而不是每个项目保存一个互相矛盾的客户级等级。

## 3. 覆盖冲突及责任追溯

- 评分保存由数据库事务完成：服务端重新计算百分制分数/等级，写入`published_grade`、`published_score`、`published_at`并置`status=approved`（历史数据兼容值，在界面显示为“已生效 · 负责人自主评级”，**不是经理批准**）。
- 数据库保存`assessor_profile_id`作为最近修改人，读API按现有客户可见性返回评级人姓名；每次变更向`cpc_audit_log`写入前后内容及`POTENTIAL_RATING_OWNER_PUBLISHED`，可审计。
- 乐观版本号`version`保留：多人同时打开同一客户时，后提交的旧版本返回`VERSION_CONFLICT`，必须刷新重新确认，**不能静默覆盖**前一位负责人。
- 项目负责人调离项目、项目取消/丢单后，不再凭该项目拥有改评权限。已有P等级保持历史有效，不在项目关系变化时自动降级。
- 与原**A/B/C回访建议**无关，不创造新销售任务。

## 4. UI与API

- 客户列表保留 R/P 等级、真实维护人，增加最近P评分人的显示；将“潜力评级待审核”改为“潜力未评级”。
- 客户详情保留紧凑、默认折叠的P评分区。客户池负责人或符合条件的**项目负责人**可以点击“编辑评级”；完成五项评分、至少20字依据，点击“保存潜力评级并生效”，保存成功后自动折叠并显示新P等级。
- 历史旧版未生效草稿用“旧版草稿/待审，重新保存即生效”提示，不假装经理审核。
- 原`PATCH /api/customer-projects/customer-ratings`经理审批端点移除，现返回默认HTTP 405。原审查RPC保留仅供历史追溯但撤销`authenticated`、`anon`、`PUBLIC`的EXECUTE许可。
- 原`POST`评分接口内部强制`p_submit=true`，前端无隐藏草稿接口可绕开自动生效流程；数据库保留原RPC签名满足兼容性并防止旧版本误写销售计划。
