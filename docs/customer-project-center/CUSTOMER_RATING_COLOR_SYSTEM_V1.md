# CPC 客户双评级｜视觉颜色规范 V1

适用范围：客户列表、客户详情、潜力评分试算、经理审核，未来拓展到CPC管理看板时应共用一个组件。

## 1. 两条信息轴，绝不依赖单一颜色辨识

- **R 实际评级**：深色实心、方角卡片式标签，始终标记「实际 R-级别」；代表财务核实后的过去12个月回款，不允许业务员手动调整。
- **P 潜力评级**：浅色底、较粗彩色描边、圆形胶囊标签，始终标记「潜力 P-级别」；代表已获管理者审核的未来业务价值潜力。
- **待审核/试算**：仍采用 P 的等级色系，但使用虚线边框及 **「试算·未生效」** 字样；绝不能覆盖已批准的 P 等级。
- **N（未归类）**：两个轴**全部使用中性灰色**、显示「未归类」。这代表财务数据缺失或潜力未正式审核，**不是 D 级**。

## 2. 七级标准（R与P的同级使用相同色相）

| 等级 | 色系（深色基准） | 视觉含义 |
| --- | --- | --- |
| SS | 金 `yellow-700` | 最高等级、超核心 |
| S | 紫 `violet-700` | 核心/极高潜力 |
| A | 蓝 `blue-700` | 高价值/高潜力 |
| B | 绿 `emerald-700` | 中等级，持续维护 |
| C | 橙 `orange-700` | 一般等级 |
| D | 红 `rose-700` | 经核实的最低等级；**不等同于坏账、拒收或信用风险** |
| N | 灰 `slate-100/slate-600` | 未归类，证据不完整 |

注意：R和P的色**相**相同，但外形、明暗、填充效果不同；等级不同则色相不同。不能通过红色独断客户信用风险，风险标签应为独立业务状态。

## 3. 实现与可访问性

- 单一权威色彩定义：`src/components/customer-projects/customer-rating-colors.ts`。
- 展示组件及可折叠说明：`src/components/customer-projects/CustomerRatingBadge.tsx`。
- 客户列表、客户详情、试算、经理待审核不可重复硬编码颜色。
- 颜色只是视觉辅助；保留 R/P、SS/S/A/B/C/D/N 文本和中文「未归类」。
- 显示组件有中文 aria-label，屏幕阅读器能读取类型/级别/待审核状态。
- 样式以静态 Tailwind utility 字符串定义在 `src/components`，因为现有 Tailwind 配置只扫描 src/components 与 src/app，而不扫描 src/lib；动态拼色容易造成上线后颜色丢失。
- 原有老客户30/60/90天的 A/B/C 关系回访分类不使用该配色，不改变原业务分类。
- 只涉及前端显示代码，无数据库迁移、财务数据、客户评级数据、权限及评分规则修改。

## 4. 验收

- 任意 SS/S/A/B/C/D 的 R 与 P：色相相同但实心方角/浅色描边圆角清晰区分。
- 任意不同级别：颜色不同；SS金、S紫、A蓝、B绿、C橙、D红。
- N：一律灰色 + 「未归类」，不得自动渲染为 D 或红色。
- 潜力草稿/经理待审核：相应等级色 + 虚线描边 +「试算·未生效」，并与正式潜力等级分别显示。
- 两个页面均显示同一说明与同一组件，保留原A/B/C关系回访分类语义；失败的数据服务不得伪造评级。
