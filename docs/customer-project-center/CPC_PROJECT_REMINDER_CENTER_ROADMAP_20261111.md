# HongdaOS CPC 项目推进提醒中心｜P1 站内预览与 P2 可信推送规划

日期：2026-11-11。权限：仅复用 CPC 项目级 RLS，不扩展客户、员工档案、财务权限。发布：本 PR 只读站内预览，不进行生产数据库变更、不主动推送。

## 一、业务目标

1. **实质推进记录空窗**：项目连续7天未出现已确认的有效进展事件，14天重点关注。
2. **关键时间到期**：正式任务和等待检查，提前48小时提示，当天与逾期清楚区分。
3. **销售开发空窗**：在职业务员连续14天未新增有效项目给出建议，30天重点关注；没有项目时基线为账号创建时间。
4. **项目缺少下一步**：进行中项目没有开放的 NEXT_ACTION 或等待未设置 next_check_at。

**正式到期**只能来自已确认的 WorkItem/等待检查；**推进空窗、开发空窗和缺下一步**都是管理观察建议，不自动构成逾期、绩效扣分或客户承诺。

## 二、P1 已实现：只读站内提醒

- 入口：客户项目 → 项目 → **项目推进提醒**。
- 页面：/customer-projects/projects/reminders，基于现有 CPC 组织/身份与 Supabase RLS 读取；无 service-role。
- 分组：全部 / 关键时间 / 项目推进 / 开发空窗；按业务员筛选仅管理者可用，向浏览器提供临时键，不提供员工 UUID。
- 点击提醒直达项目详情；读取失败时显示错误，而非误报“零提醒”。
- 北京时间，页面打开或刷新重新生成，没有自动创建任务、修改日期、消息储存、定时调度或自动发送。
- 正式到期记录取自 cpc_work_items 中开放的 NEXT_ACTION / CUSTOMER_COMMITMENT / INTERNAL_COLLABORATION / MANAGEMENT_DECISION；以及 cpc_projects.waiting_on 和 next_check_at。
- 已核实项目进展取自 cpc_project_events，并严格复用 domain.ts 的 projectEventCountsAsEffectiveProgress，不能因为编辑备注、普通联系记录 CONTACT_LOGGED 而重置停滞周期。
- 新增项目以 cpc_projects.created_at 为准；无正式项目记录的线索不算新增。
- 等待客户且有有效检查时间的项目，不因为正常等待而被当作停滞；检查时间到期只进入正式检查提醒。
- 完成/取消任务、关闭/归档项目均不纳入活跃到期风险。
- 安全上限：500 项目、1000 开放任务、2000 项目事件、100 员工；任一达到上限则拒绝生成不完整报表。
- 用户只能看到 RLS 允许的项目；管理员/经理有组织级视图，销售无越权资料。

### 当前明确限制

P1 是**站内按需查看**，不是主动推送。员工若不打开页面不会收到消息。尚无已读/稍后提醒/免打扰、邮件/企业微信/WhatsApp、Delivery Log、自动调度或升级推送。
7/14天及14/30天阈值是默认试运行建议，未获得正式 KPI 或员工考核授权。

## 三、P2 建议：可靠定时推送（尚未实施）

1. **渠道与绑定**：优先确认企业微信应用消息或公司邮箱等内部渠道；先验证收件人身份和隐私边界，不向未确认的个人 WhatsApp 私聊推送客户资料。
2. **推送时间**：建议北京时间工作日09:00汇总；重要客户承诺逾期可以二次补发，晚间22:00—08:30静默；节假日按公司日历配置。
3. **接收人**：任务提醒找任务 assignee_profile_id；等待检查与项目进展提醒找项目 owner_profile_id；开发空窗先通知负责人本人，30天后纳入管理员汇总。
4. **去重**：独立、最小权限的投递队列/日志，而不是重复生成 WorkItem。幂等键：org、recipient、source_type、source_id、effective_at、channel、policy_version、delivery_window。改期生成新的 occurrence，旧 occurrence 取消。
5. **状态一致性**：执行前重读有效业务源；完成/取消/改期的任务不能继续发送旧消息；失败重试带退避、上限与审计。
6. **节流**：普通提醒同节点每天最多一次，逾期升级限定次数，每人每天限制条数，非紧急尽量汇总。
7. **调度**：采用 Supabase Cron+Edge Functions 或已有 Vercel Cron，由受限服务身份执行，密钥存在平台 Secrets/Vault，不暴露在客户端。
8. **发布门槛**：P2 单独批准渠道/定时费用/生产数据库迁移/权限、免打扰及回滚；先在隔离库与沙盒收件人完成10轮重复触发、失败恢复和越权拒绝。
9. **闭环**：提醒点开回到 CPC 项目；真实项目推进仍需走现有受控命令，通知系统只读，不替代业务事实。

## 四、验收边界

- 工作节点的北京时间到期、逾期、48小时窗口；
- 关闭任务不显示，缺下一步仅为建议；
- CONTACT_LOGGED 不重置有效推进计时，正式报价等有效事件会重置；
- 等待有检查时间不能误判停滞；
- 新员工和离职人员不会被无故评为停滞；
- RLS、安全上限、无外部推送；
- 不修改 R/P 客户评级、人员归属、工资提成、回款或独立车间系统。
