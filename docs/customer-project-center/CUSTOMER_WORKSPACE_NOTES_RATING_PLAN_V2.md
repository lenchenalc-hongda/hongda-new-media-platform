# CPC 客户详情 V2｜客户备注、独立潜力评分、常驻开发计划

状态：2026-10-25 开发/测试候选版本。**不得未经独立授权合并 Production 或将新迁移执行到生产数据库。**

## 已确认的用户体验

1. **客户备注**：在客户详情新增独立记录区域，允许有归属权限的客户负责人/管理员/经理填写，保存后长期保留。可记录沟通偏好、品质注意事项、客户特殊要求。客户列表仅显示简短预览，完整内容在详情查看；这不是客户主数据，**不覆盖车间客户池**。
2. **潜力评级**：进入客户详情时默认只显示 R/P 等级、已审核分数、审批状态和维护人。点击“编辑评级”才显示五项 0–5 分评估及“客户事实与可核实依据”。评分草稿保存后自动折叠；提交经理审核后自动折叠。经理点击同一个入口展开待审分数与证据，可批准/退回。
3. **客户开发机会与销售行动**：在评级折叠之外常驻展示“未来12个月主要开发机会”“预计可争取年采购金额（人民币元，非实际回款）”“具体下一步销售行动”“下一步检查日期（北京时间）”。独立保存，不要求先完成五项潜力评分。非空机会内容至少10字，非空下一步行动至少5字；金额缺证据可留空。与CPC正式项目/任务并行，不自动生成无依据的销售任务。
4. 评级、备注与开发计划的保存互不影响。**新评估提交或草稿保存不再重写开发机会、金额、行动或日期；独立更新计划不修改P正式评级。** 被经理批准的P等级在本轮重评审批前保持有效；R等级仍依赖真实财务。

## 数据结构与权限

- 继续使用现有 `cpc_customer_potential_assessments` 保存五项评分、事实依据、版本、P待审及正式等级。
- 新增 `cpc_customer_workspaces`（仅CPC内部数据，不另建客户主档）保存 `customer_note` + `note_version`、销售计划四项内容 + `plan_version`，一客户一行、org隔离、双独立版本锁。新增唯一键(org_id,customer_reference_id)及客户和操作者复合外键。
- 原客户名称、外部归属映射、R/S/SS阈值、财务记录、工资及提成完全不修改。
- 新表启用 RLS，已登录用户仅能读取原本允许查看的客户记录；`authenticated` 仅有 SELECT，无直接 INSERT/UPDATE。写操作经受控 RPC，要求真实用户、活跃profile、公司组织校验，并遵守 `cpc_can_assess_customer_rating` 的“真实客户负责人/经理/admin”权限。
- 操作时按具体章节记录独立历史与版本冲突：`CUSTOMER_NOTE_SAVED`、`CUSTOMER_DEVELOPMENT_PLAN_SAVED`；评分原审计和管理者审批审计保留。
- 旧评估记录如填写过机会、金额、行动或日期，在**首次执行新增迁移时**只复制到新工作区（冲突时不会覆盖已有工作区），不删除旧数据，保证历史计划不丢失。以后客户列表和详情均以新工作区为开发计划读取来源。

## Dev 与 Production 门禁

本轮允许开发环境验证；**不授权生产迁移或正式发布**。

1. Dev SQL 增量迁移、无真实客户测试数据；
2. Dev事务测试：先计划→备注→评分→经理批准→计划改动仍保持已批准评级；双版本冲突与审计；测试事务ROLLBACK；
3. Dev RLS/角色 GRANT 查询；anon 不可读/写/调用，authenticated 不可直接写表；所有 RPC 由DB验证真实负责人；
4. GitHub CI、TypeScript、Next build、CPC 回归测试通过，Vercel Preview READY；
5. 后续需独立批准 Production **迁移+发版**：迁移先备份核验旧评估计划数据，再一次性应用新增表/RLS/RPC，核验迁移行数及权限，随后合并经检查的 PR HEAD；Vercel READY 后按真实账户测试最低权限和保存闭环。

**注意**：在 Production 迁移尚未执行时，预览环境如果仍连接生产 Supabase，评级 API 会返回服务未初始化，不能把前端 BUILD READY 当作登录态真实功能验收；在Dev已测试的数据库事务才是当前数据层验证证据。
